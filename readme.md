# 要件

themes 配下を git 管理しており、環境構築に使用するツールは問わない。ただし、PHP と Wordpress のバージョンは本番環境に近いバージョンで構築するのが望ましい。

本番環境のバージョン情報（2024.02.14 時点）  
PHP: 8.2.12  
Wordpress: 6.41  
サーバー: Apache

# Wordpress の環境構築手順

プラグイン(wp-content/plugins/_)やメディア画像(wp-content/upload/_)は Git 管理が煩雑になる他、後で説明するプラグインを介してインストールすることを想定しているため、Git の管理していない。

## 1.wordpress のインストール

任意のツール（以下に例をあげた）のいずれかを使用して、wordpress 環境を構築する。（各ツールの使用方法は割愛）

- xampp/mamp
- local(旧:local by flywheel)
- vagrant
- docker

## 2.仮のサイト情報を設定する

任意のツールで Wordpress をインストール後、言語設定や任意のユーザ名、パス、サイト情報を登録し、管理画面へアクセスする.  
※後述するバックアップファイルのインポートでこの設定内容は上書きされるので、仮のものと考えて良い。

## 3.プラグインのインストール

管理画面左ペインより、「プラグイン(plugin)」を選択し、「新規プラグインを追加」で「all in one wp-migration」を検索、インストール、有効化する

## 4.バックアップファイルのインポート

DB、メディア、プラグイン、記事情報等を含んだバックアップファイル（Backlog）をダウンロードしておき、「All-in-one WP Migration」>> 「インポート」でファイル指定する。  
※このバックアップファイルにテーマファイルが含まれていると、theme 配下の.git が消えてしまうため、バックアップファイルにテーマファイルは含めないこと。

## 5.再ログイン

インポート完了後にブラウザを再読み込みすると、ログイン画面にリダイレクトされるのでユーザ名、パスワードを入力する。（Backlog 参照）  
※「手順 2」で設定したユーザ名、パスワードはバックアップファイルにより上書かれた後、使えなくなります。  
ログイン後、各ページが問題なく表示できていれば環境構築は完了

# バックアップファイルの作成

プラグイン情報やフィールドの追加など、DB まわりの修正が行われた場合は、バックアップファイルを生成し、Backlog などで更新・管理すること。

◾️ バックアップファイルの作成  
1.「All-in-one WP Migration」>> 「エクスポート」  
2.「高度なオプション」より「テーマをエクスポートしない」にチェックをいれる  
※テーマ配下のコードは Git で取得可能かつ BP ファイルのインストール先で.git を上書いて消してしまうため、エクスポート対象からテーマを外すこと。  
3.生成した BP ファイルを Backlog 等へ残す。

# Wordpress の環境構築手順（ver 柏木）

大まかな流れは上記に触れた通りですが、柏木が使用していた開発環境(docker)の手順も残しておきます。

# 要件

- 統合開発環境に VScode を使用
- Docker for Desktop をインストール済みであること

## 1.環境構築ファイルをダウンロード

Backlog より,zip ファイルをダウンロードし、任意のディレクトリに配置。  
htttp:/**\***

## 2.リモートリポジトリからクローン

「任意のディレクトリ/wp-data/media1-theme」配下にリポジトリをクローンする。

社内 Github  
https://github.com/kannart/media1

## 3.プラグインのインストール・有効化

プロジェクトを VScode より起動すると、推奨プラグインをインストールするサジェストが表示されるので、インストール・有効化する。  
※サジェストがない婆は左ペインの「拡張機能」より推奨プラグインをインストールする。

## 4.環境変数を設置する

Backlog より、.env をインストールしてルートディレクトリに配置しておく

## 5.イメージ生成/コンテナ起動

docker for desctop が起動していることを確認後、ターミナルで docker-compose.yml が配置されているディレクトリへ移動し、下記コマンドを実行（イメージ生成、コンテナ起動）

```
docker-compose up -d
```

上記のコマンドでコンテナが正常に起動しない or エラーが生じる等の場合は、下記の項目に該当しないかチェックする

- 「手順 1」でおとした各環境ファイルの改行コードが lf になっているか。（crlf だと正常に起動できない場合がある）  
  ※vscode のプラグイン「editorconfig」が入っていれば、保存時（Ctrl+s）に整形処理が働く
- 他ツールの仮想環境で使用中のポート番号と重複していないか
- 環境構築に必要なファイルに不足はないか。

コンテナが正常に起動しなかった場合は docker for desctop よりコンテナ、イメージ、ボリュームを一度削除してから改めて、上記のコマンドを打ち直して再立ち上げをする。  
※削除する順番としてはコンテナを最初に削除するとよい。コンテナに紐いていないイメージやボリュームはステータスが unused に変わり、判別しやすいため。

※設定ファイルなどの軽微な変更であれば、下記コマンドで適用できる場合もある

```
docker-compose up -d --build
```

## 6.仮のサイト情報を設定する

docker for desctop の wordpress コンテナに指定されているポート番号へアクセスし、言語設定や任意のユーザ名、パス、サイト情報を登録し、管理画面へアクセスする。

## 7.プラグインのインストール

管理画面左ペインより、「プラグイン(plugin)」を選択し、「新規プラグインを追加」で「all in one wp-migration」を検索、インストール、有効化する

## 8.バックアップファイルのインポート

DB、メディア、プラグイン、記事情報等を含んだバックアップファイル（Backlog）をダウンロードしておき、「All-in-one WP Migration」>> 「インポート」でファイル指定する。  
※このバックアップファイルにテーマファイルが含まれていると、theme 配下の.git が消えてしまうため、バックアップファイルにテーマファイルは含めないこと。

## 9.再ログイン

インポート後はブラウザを再読み込みし、ユーザ名、パスワードを入力する。（Backlog 参照）  
各ページが問題なく表示できていれば環境構築は完了
